OVERVIEW

Bản đồ hệ sinh thái React — dùng thư viện nào cho việc gì?

React chỉ lo phần UI — mọi thứ khác (routing, form, state, gọi API) đều cần thư viện ngoài

React "tối giản" theo chủ đích

Bản thân React chỉ giải quyết một việc: dựng UI từ state. Điều hướng trang, quản lý form phức tạp, chia sẻ state giữa nhiều component, gọi API và cache dữ liệu... đều không nằm trong React core — đó là lý do hệ sinh thái thư viện xung quanh React rất lớn. Nắm được "việc nào dùng thư viện nào" giúp bạn không phải tự viết lại những gì cộng đồng đã tối ưu sẵn.

main.jsx / App.jsx — khai báo RoutesROUTER
import { BrowserRouter, Routes, Route } from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <Routes>
        {/* path="/" -> trang chủ */}
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        {/* :id -> tham số động, đọc bằng useParams */}
        <Route path="/products/:id" element={<ProductDetail />} />
        {/* route lồng nhau -> dùng <Outlet /> trong Layout để render con */}
        <Route path="/dashboard" element={<DashboardLayout />}>
          <Route index element={<DashboardHome />} />
          <Route path="settings" element={<Settings />} />
        </Route>
        {/* path="*" -> bắt mọi URL không khớp -> trang 404 */}
        <Route path="*" element={<NotFound />} />
      </Routes>
    </BrowserRouter>
  );
}
✅
Ghi nhớ: BrowserRouter bọc ngoài cùng app (thường đặt trong main.jsx). Routes chỉ chứa các Route. Mỗi Route ánh xạ 1 path tới 1 component qua prop element.

useNavigate, useParams & useSearchParams

3 hook của react-router-dom dùng nhiều nhất sau Link/NavLink

ProductDetail.jsx — điều hướng bằng code + đọc URLHOOKS
import { useNavigate, useParams, useSearchParams } from "react-router-dom";

function ProductDetail() {
  // useParams -> đọc tham số động trên path, vd path="/products/:id"
  const { id } = useParams();

  // useSearchParams -> đọc/ghi query string ?sort=price&page=2
  const [searchParams, setSearchParams] = useSearchParams();
  const sort = searchParams.get("sort") ?? "newest";

  // useNavigate -> chuyển trang bằng code (sau khi submit, sau khi xoá...)
  const navigate = useNavigate();

  async function handleDelete() {
    await deleteProduct(id);
    navigate("/products"); // chuyển về danh sách sau khi xoá
  }

  function changeSort(value) {
    setSearchParams({ sort: value }); // cập nhật URL: ?sort=price
  }

  return (
    <div>
      <p>Đang xem sản phẩm #{id}, sắp xếp theo {sort}</p>
      <button onClick={handleDelete}>Xoá sản phẩm</button>
    </div>
  );
}

useParams()Đọc tham số động trong pathconst {'{'} id {'}'} = useParams()
useSearchParams()Đọc/ghi query string trên URLsearchParams.get("page")
useLocation()Lấy thông tin URL hiện tại (pathname, state...)location.pathname

Lỗi hay gặp: Đừng dùng window.location.href để chuyển trang trong app React Router — nó làm reload toàn bộ trang, mất hết state. Luôn dùng navigate() hoặc <Link>.

React Hook Form — cơ bản

Thư viện quản lý form phổ biến nhất: ít re-render, ít code, hiệu năng cao

Vì sao không tự quản form bằng useState?

Nếu quản mỗi input bằng 1 useState, mỗi lần gõ phím component sẽ re-render lại toàn bộ form. Với form nhiều field hoặc form phức tạp, việc này gây giật, chậm. react-hook-form dùng ref & uncontrolled input để hạn chế tối đa re-render, đồng thời cung cấp validate, hiển thị lỗi, submit... gọn trong 1 API duy nhất.

terminalINSTALL
$ npm install react-hook-form
LoginForm.jsx — register + handleSubmitRHF
import { useForm } from "react-hook-form";

function LoginForm() {
  // register -> gắn input vào form; handleSubmit -> bọc hàm submit + tự validate
  // formState.errors -> object chứa lỗi validate của từng field
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm();

  function onSubmit(data) {
    // data = { email: "...", password: "..." } -> đúng tên field đã register
    console.log(data);
  }

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input
        {...register("email", {
          required: "Email là bắt buộc",
          pattern: { value: /^\S+@\S+\.\S+$/, message: "Email không hợp lệ" },
        })}
        placeholder="Email"
      />
      {errors.email && <p className="err">{errors.email.message}</p>}

      <input
        type="password"
        {...register("password", { required: true, minLength: { value: 6, message: "Tối thiểu 6 ký tự" } })}
        placeholder="Mật khẩu"
      />
      {errors.password && <p className="err">{errors.password.message}</p>}

      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? "Đang đăng nhập..." : "Đăng nhập"}
      </button>
    </form>
  );
}
✅
3 thứ cần nhớ: register("tên", rules) gắn input + khai báo rule validate ngay tại chỗ · handleSubmit(onSubmit) tự validate trước khi gọi onSubmit · formState.errors.tenField để hiển thị lỗi.

Tách rule validate ra schema riêng — tái sử dụng được, dễ đọc hơn khai báo rời rạc

zodResolver — kết hợp Zod với React Hook Form
terminalINSTALL
$ npm install zod @hookform/resolvers
RegisterForm.jsx — schema + resolverZOD
import { z } from "zod";
import { zodResolver } from "@hookform/resolvers/zod";
import { useForm } from "react-hook-form";

// Khai báo schema 1 lần -> dùng lại được cho validate FE lẫn hiển thị type (TS)
const schema = z.object({
  email: z.string().email("Email không hợp lệ"),
  password: z.string().min(6, "Tối thiểu 6 ký tự"),
  confirmPassword: z.string(),
}).refine((data) => data.password === data.confirmPassword, {
  message: "Mật khẩu xác nhận không khớp",
  path: ["confirmPassword"], // lỗi hiện ở field nào
});

function RegisterForm() {
  const { register, handleSubmit, formState: { errors } } = useForm({
    resolver: zodResolver(schema), // gắn schema vào react-hook-form
  });

  return (
    <form onSubmit={handleSubmit((data) => console.log(data))}>
      <input {...register("email")} />
      {errors.email && <p>{errors.email.message}</p>}
      <input type="password" {...register("password")} />
      {errors.password && <p>{errors.password.message}</p>}
      <button type="submit">Đăng ký</button>
    </form>
  );
}
💡
Zod vs Yup: Cả hai đều tốt. Zod phổ biến hơn trong dự án TypeScript vì tự suy ra type từ schema (z.infer<typeof schema>). Yup lâu đời hơn, cú pháp tương tự, phổ biến trong dự án JS thuần hoặc đi cùng Formik.

Controller, useFieldArray & form nâng cao

Xử lý input không phải HTML thuần (select custom, date picker...) và danh sách field động

Controller — dùng khi input là component UI thư viện ngoài

register chỉ hoạt động tốt với input HTML thuần. Với các component như <DatePicker>, <Select> custom (không nhận ref trực tiếp), cần bọc bằng <Controller>.

Controller — input customCONTROLLER
import { useForm, Controller } from "react-hook-form";
import Select from "react-select";

function CityForm() {
  const { control, handleSubmit } = useForm();
  const options = [{ value: "hn", label: "Hà Nội" }, { value: "hcm", label: "TP.HCM" }];

  return (
    <form onSubmit={handleSubmit((data) => console.log(data))}>
      <Controller
        name="city"
        control={control}
        rules={{ required: true }}
        render={({ field }) => <Select {...field} options={options} />}
      />
      <button type="submit">Lưu</button>
    </form>
  );
}
useFieldArray — danh sách field động (thêm/xoá dòng)
InvoiceForm.jsx — thêm/xoá dòng sản phẩmFIELD-ARRAY
import { useForm, useFieldArray } from "react-hook-form";

function InvoiceForm() {
  const { control, register, handleSubmit } = useForm({
    defaultValues: { items: [{ name: "", qty: 1 }] },
  });
  // fields -> mảng field hiện có; append/remove -> thêm/xoá 1 dòng
  const { fields, append, remove } = useFieldArray({ control, name: "items" });

  return (
    <form onSubmit={handleSubmit((data) => console.log(data))}>
      {fields.map((field, index) => (
        <div key={field.id}> {/* field.id ổn định, không dùng index làm key */}
          <input {...register(`items.${index}.name`)} placeholder="Tên SP" />
          <input type="number" {...register(`items.${index}.qty`)} />
          <button type="button" onClick={() => remove(index)}>Xoá</button>
        </div>
      ))}
      <button type="button" onClick={() => append({ name: "", qty: 1 })}>+ Thêm dòng</button>
      <button type="submit">Lưu hoá đơn</button>
    </form>
  );
}
⚠️
Lưu ý: Khi render fields, luôn dùng field.id (do useFieldArray tự sinh) làm key — không dùng index, vì khi thêm/xoá dòng ở giữa, index sẽ bị lệch và React render nhầm dữ liệu.

Context API — chia sẻ state không cần thư viện

Built-in trong React — đủ dùng cho state ít thay đổi (theme, auth user, ngôn ngữ...)

Tạo Context + Provider + hook đọc context
AuthContext.jsxCONTEXT
import { createContext, useContext, useState } from "react";

// 1. Tạo context — giá trị mặc định chỉ dùng khi thiếu Provider
const AuthContext = createContext(null);

// 2. Provider — bọc quanh phần cây component cần dùng chung state
export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);

  function login(userData) { setUser(userData); }
  function logout() { setUser(null); }

  return (
    <AuthContext.Provider value={{ user, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

// 3. Custom hook -> nơi duy nhất gọi useContext, tiện dùng & báo lỗi rõ ràng
export function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("useAuth phải dùng bên trong AuthProvider");
  return ctx;
}
App.jsx & Profile.jsx — bọc Provider & dùng hookUSAGE
// App.jsx — bọc Provider quanh app (hoặc phần cây cần dùng)
function App() {
  return (
    <AuthProvider>
      <Profile />
    </AuthProvider>
  );
}

// Profile.jsx — component con nào cũng đọc được, không cần truyền props qua từng cấp
function Profile() {
  const { user, logout } = useAuth();
  if (!user) return <p>Chưa đăng nhập</p>;
  return <button onClick={logout}>Đăng xuất {user.name}</button>;
}
⚠️
Giới hạn của Context: Mọi component gọi useContext sẽ re-render khi value đổi — kể cả khi chỉ 1 field trong value thay đổi. Với state cập nhật liên tục (giỏ hàng, filter danh sách...), Context dễ gây re-render thừa → cân nhắc Zustand/Redux.

cartStore.js — tạo storeZUSTAND
import { create } from "zustand";

// create() -> trả về 1 hook dùng thẳng trong component, không cần Provider
export const useCartStore = create((set, get) => ({
  items: [],
  addItem: (product) =>
    set((state) => ({ items: [...state.items, product] })),
  removeItem: (id) =>
    set((state) => ({ items: state.items.filter((i) => i.id !== id) })),
  clear: () => set({ items: [] }),
  // get() -> đọc state hiện tại bên trong 1 action khác (tính tổng tiền)
  total: () => get().items.reduce((sum, i) => sum + i.price, 0),
}));
CartBadge.jsx — dùng store trực tiếp, không ProviderUSAGE
import { useCartStore } from "./cartStore";

function CartBadge() {
  // Selector -> chỉ subscribe field "items", component KHÔNG re-render khi field khác đổi
  const items = useCartStore((state) => state.items);
  return <span>Giỏ hàng: {items.length}</span>;
}

function AddToCartButton({ product }) {
  const addItem = useCartStore((state) => state.addItem);
  return <button onClick={() => addItem(product)}>Thêm vào giỏ</button>;
}
✅
Vì sao Zustand ít gây re-render hơn Context: Mỗi component chỉ subscribe đúng phần state nó cần qua selector (state => state.items) — field khác trong store đổi sẽ không làm component này render lại, khác với Context vốn re-render toàn bộ khi value đổi.

counterSlice.js — createSliceSLICE
import { createSlice } from "@reduxjs/toolkit";

// createSlice -> gộp state ban đầu + reducers + action creators trong 1 chỗ
const counterSlice = createSlice({
  name: "counter",
  initialState: { value: 0 },
  reducers: {
    // Nhờ Immer bên trong RTK, có thể viết "mutate" trực tiếp mà vẫn immutable
    increment: (state) => { state.value += 1; },
    decrement: (state) => { state.value -= 1; },
    addBy: (state, action) => { state.value += action.payload; },
  },
});

export const { increment, decrement, addBy } = counterSlice.actions;
export default counterSlice.reducer;

// store.js
import { configureStore } from "@reduxjs/toolkit";

export const store = configureStore({
  reducer: { counter: counterReducer }, // gom nhiều slice tại đây

// main.jsx — bọc <Provider> ở gốc app (chỉ 1 lần, khác Context — không cần nhiều Provider)
<Provider store={store}><App /></Provider>

// Counter.jsx — đọc/ghi state bằng useSelector & useDispatch
import { useSelector, useDispatch } from "react-redux";
import { increment, decrement } from "./counterSlice";

function Counter() {
  const value = useSelector((state) => state.counter.value);
  const dispatch = useDispatch();
  return (
    <>
      <button onClick={() => dispatch(decrement())}>-</button>
      <span>{value}</span>
      <button onClick={() => dispatch(increment())}>+</button>
    </>
  );
}

api/axiosClient.js — instance dùng chung + interceptorAXIOS
import axios from "axios";

// Tạo instance riêng -> cấu hình 1 lần, dùng lại khắp app
const api = axios.create({
  baseURL: "https://api.example.com",
  timeout: 10000,
});

// Interceptor request -> tự động gắn token vào mọi request
api.interceptors.request.use((config) => {
  const token = localStorage.getItem("token");
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// Interceptor response -> xử lý lỗi tập trung, vd token hết hạn thì logout
api.interceptors.response.use(
  (res) => res,
  (error) => {
    if (error.response?.status === 401) {
      localStorage.removeItem("token");
      window.location.href = "/login";
    }
    return Promise.reject(error);
  }
);

export default api;

UserList.jsx — useQuery thay cho useEffect + fetch thủ côngUSE-QUERY
import { useQuery } from "@tanstack/react-query";
import { userApi } from "./userApi";

function UserList() {
  // queryKey -> định danh dữ liệu để cache; queryFn -> hàm lấy dữ liệu
  const { data, isLoading, isError, error } = useQuery({
    queryKey: ["users"],
    queryFn: userApi.getAll,
    staleTime: 60_000, // 1 phút -> trong thời gian này không tự fetch lại
  });

  if (isLoading) return <p>Đang tải...</p>;
  if (isError) return <p>Lỗi: {error.message}</p>;

  return (
    <ul>
      {data.map((u) => <li key={u.id}>{u.name}</li>)}
    </ul>
  );
}
CreateUserForm.jsx — useMutation cho POST/PUT/DELETEUSE-MUTATION
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { userApi } from "./userApi";

function CreateUserForm() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: userApi.create,
    onSuccess: () => {
      // Tạo xong -> đánh dấu cache "users" là cũ -> TanStack Query tự fetch lại
      queryClient.invalidateQueries({ queryKey: ["users"] });
    },
  });

  function handleSubmit(e) {
    e.preventDefault();
    mutation.mutate({ name: "Người dùng mới" });
  }

  return (
    <form onSubmit={handleSubmit}>
      <button type="submit" disabled={mutation.isPending}>
        {mutation.isPending ? "Đang tạo..." : "Tạo user"}
      </button>
    </form>
  );
}
✅
useQuery vs useMutation: useQuery dùng để đọc dữ liệu (GET), tự chạy khi component mount. useMutation dùng để thay đổi dữ liệu (POST/PUT/DELETE), chỉ chạy khi bạn gọi mutate().

useContext & useReducer

Đọc context (đã nói ở phần State) & quản lý state phức tạp có nhiều hành động

useReducer — thay useState khi state có nhiều action liên quan
cartReducer.js — reducer thuầnuseReducer
// reducer -> hàm thuần (state, action) => newState, KHÔNG mutate state cũ
function cartReducer(state, action) {
  switch (action.type) {
    case "ADD_ITEM":
      return { ...state, items: [...state.items, action.payload] };
    case "REMOVE_ITEM":
      return { ...state, items: state.items.filter((i) => i.id !== action.payload) };
    case "CLEAR":
      return { ...state, items: [] };
    default:
      return state;
  }
}

function Cart() {
  const [state, dispatch] = useReducer(cartReducer, { items: [] });

  return (
    <button onClick={() => dispatch({ type: "ADD_ITEM", payload: { id: 1 } })}>
      Thêm ({state.items.length})
    </button>
  );
}
📌
Khi nào chọn useReducer thay useState: Khi state có nhiều field liên quan với nhau, hoặc có nhiều "hành động" khác nhau tác động lên cùng 1 state (thêm, xoá, sửa, reset...) — gom logic cập nhật vào 1 reducer giúp code dễ theo dõi hơn nhiều useState rời rạc.

Tự viết Custom Hook

Đóng gói logic tái sử dụng — chỉ là 1 hàm JS bắt đầu bằng "use"

useDebounce.js — hook debounce tái sử dụngCUSTOM HOOK
import { useState, useEffect } from "react";

// Nhận value + delay -> trả về giá trị đã "trễ" delay ms so với value gốc
function useDebounce(value, delay = 400) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer); // huỷ timer cũ nếu value đổi trước khi hết delay
  }, [value, delay]);

  return debounced;
}

export default useDebounce;
SearchBox.jsx — dùng lại custom hook, gọn như hook có sẵnUSAGE
function SearchBox() {
  const [keyword, setKeyword] = useState("");
  const debouncedKeyword = useDebounce(keyword, 500);

  useEffect(() => {
    if (!debouncedKeyword) return;
    searchApi(debouncedKeyword); // chỉ gọi API sau khi người dùng ngừng gõ 500ms
  }, [debouncedKeyword]);

  return <input value={keyword} onChange={(e) => setKeyword(e.target.value)} />;
}
