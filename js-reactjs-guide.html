JavaScript & React liên hệ với nhau thế nào?

React chỉ là một thư viện JS — hiểu sâu JS giúp viết React tốt hơn rất nhiều

React không có "cú pháp riêng" — tất cả đều là JS

Nhiều người mới học React nghĩ JSX, hooks, props... là những "khái niệm React" tách biệt. Thực ra React được xây trên JavaScript thuần: JSX chỉ là cú pháp gọi createElement(), một component chỉ là một hàm JS trả về giá trị, và hooks chỉ là các hàm JS tuân theo quy tắc gọi hàm nhất định. Càng giỏi JS hiện đại (ES6+), bạn càng viết React sạch, ít bug và dễ tối ưu hơn.

Spread & Rest — cập nhật object/array không mutate
spread-rest.jsSPREAD
// Spread object — tạo bản sao mới kèm field được ghi đè
const updatedUser = { ...user, age: user.age + 1 };

// Spread array — nối, chèn, sao chép mà không mutate mảng gốc

function Button({ children, ...htmlProps }) {
  return <button {...htmlProps}>{children}</button>;
}
// -> <Button onClick={...} disabled className="x"> tự động truyền hết vào <button>
⚠️
Lưu ý: Spread chỉ tạo bản sao nông (shallow copy). Nếu object có thuộc tính lồng nhau (nested object), spread chỉ copy tầng ngoài — tầng trong vẫn trỏ chung tham chiếu. Muốn sửa field lồng sâu, phải spread từng cấp: { ...state, user: { ...state.user, name: "x" } }.

Array methods thiết yếu khi render danh sách

map, filter, reduce, find, some/every — trái tim của render động trong JSX

TodoList.jsx — map, filter, reduce trong JSXARRAY
function TodoList({ todos }) {
  // filter -> lọc danh sách con trước khi map
  const activeTodos = todos.filter((t) => !t.done);

  // reduce -> tính tổng/đếm từ mảng
  const doneCount = todos.reduce((sum, t) => t.done ? sum + 1 : sum, 0);

  return (
    <>
      <p>Hoàn thành: {doneCount}/{todos.length}</p>
      <ul>
        {/* map -> render mảng thành JSX, luôn kèm key ổn định */}
        {activeTodos.map((todo) => (
          <li key={todo.id}>{todo.title}</li>
        ))}
      </ul>
    </>
  );
}

filter()Lọc bớt phần tử theo điều kiệnTìm kiếm, tab "chưa xong/đã xong"
reduce()Gộp mảng thành 1 giá trịTính tổng giỏ hàng, đếm, group by
find()Lấy 1 phần tử đầu tiên khớpTìm user theo id
some() / every()Kiểm tra điều kiện booleanDisable nút submit khi form chưa hợp lệ
🚫
Lỗi kinh điển: Dùng index làm key khi danh sách có thể thêm/xoá/sắp xếp lại — React sẽ so khớp sai phần tử, gây render nhầm state (đặc biệt với input, checkbox). Luôn dùng id ổn định từ dữ liệu làm key.

Optional Chaining, Nullish Coalescing & Template Literals

Tránh crash "Cannot read property of undefined" — lỗi runtime phổ biến nhất trong React

safe-access.jsxSAFE ACCESS
// ?. — truy cập an toàn, trả undefined thay vì throw lỗi nếu null/undefined
const city = user?.address?.city;
const firstItem = list?.[0];
onSave?.(formData);           // gọi hàm chỉ khi onSave tồn tại

// ?? — chỉ fallback khi null/undefined (khác || fallback cả 0, "", false)
const quantity = product.stock ?? 0;     // stock = 0 vẫn giữ 0, không bị ép thành fallback
const title = post.title || "Không có tiêu đề"; // || sẽ fallback nhầm khi title = ""

// Template literal — nối chuỗi + class động, rõ ràng hơn concat
const className = `btn ${isActive ? "btn-active" : ""} ${size}`;
const greeting = `Xin chào, ${user?.name ?? "bạn"}!`;
💡
Phân biệt || và ??: || coi 0, "", false đều là "falsy" nên sẽ fallback nhầm. ?? chỉ fallback khi giá trị là null hoặc undefined — an toàn hơn khi xử lý số lượng, giá tiền, chuỗi rỗng hợp lệ.

Async/Await, Promise & Fetch API

Gọi API trong useEffect và event handler đúng cách

useUserData.js — async trong useEffectASYNC
useEffect(() => {
  // useEffect không cho callback là async trực tiếp -> khai báo hàm async bên trong
  async function loadUser() {
    try {
      setLoading(true);
      const res = await fetch(`/api/users/${userId}`);
      if (!res.ok) throw new Error("Không tải được user");
      const data = await res.json();
      setUser(data);
    } catch (err) {
      setError(err.message);
    } finally {
      setLoading(false);
    }
  }
  loadUser();
}, [userId]);
handleSubmit.js — async trong event handlerEVENT
const handleSubmit = async (e) => {
  e.preventDefault();
  try {
    const res = await fetch("/api/todos", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(formData),
    });
    const created = await res.json();
    setTodos((prev) => [...prev, created]); // dùng callback form để tránh state cũ
  } catch (err) {
    console.error(err);
  }
};

Closures, this & Event Handlers

Vì sao mỗi lần render, component "chụp" lại một bản state riêng

Closure — nguồn gốc của bug "stale state" kinh điển
stale-closure.jsx — bug & cách sửaCLOSURE
// ❌ SAI — setTimeout "chụp" count tại thời điểm render, luôn cộng từ giá trị cũ
function Counter() {
  const [count, setCount] = useState(0);

  const handleDelayedAdd = () => {
    setTimeout(() => {
      setCount(count + 1); // count ở đây là giá trị "đóng băng" lúc closure tạo ra
    }, 1000);
  };

  // ✅ ĐÚNG — dùng functional update, luôn nhận state mới nhất
  const handleDelayedAddFixed = () => {
    setTimeout(() => {
      setCount((prev) => prev + 1); // React truyền state mới nhất vào prev
    }, 1000);
  };
}
🧠
Bản chất: Mỗi lần component render, một hàm mới được tạo ra và "đóng gói" (close over) các biến state tại thời điểm đó. Nếu callback được gọi sau (setTimeout, event listener, promise callback), nó vẫn dùng bản state cũ chứ không tự "thấy" state mới — trừ khi dùng functional update hoặc ref.
Arrow function & this trong JSX

Trong component hàm (function component), gần như không cần lo về this — arrow function không có this riêng, nó dùng this của scope bao ngoài, nên tránh được lỗi mất ngữ cảnh thường gặp ở class component thời trước.

event-handler-patterns.jsxHANDLER
// Truyền tham số vào handler — dùng arrow function inline
<button onClick={() => handleDelete(todo.id)}>Xoá</button>

// Lấy value từ event object

<input onChange={handleFieldChange("email")} />

useEffect, Cleanup & Dependency Array

Về bản chất chỉ là JS: side-effect, cleanup function, và so sánh mảng dependency

effect-cleanup.jsxEFFECT
useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/search?q=${query}`, { signal: controller.signal })
    .then((res) => res.json())
    .then(setResults)
    .catch((err) => {
      if (err.name !== "AbortError") console.error(err);
    });

  // cleanup — chạy trước lần effect kế tiếp & khi component unmount
  return () => controller.abort();
}, [query]); // chỉ chạy lại khi query đổi giá trị
Dependency arrayEffect chạy khi nào
useEffect(fn) — không có mảngSau mọi lần render — hiếm khi cần
useEffect(fn, [])Chỉ 1 lần sau khi mount
useEffect(fn, [query])Sau mount và mỗi khi query đổi giá trị (so sánh Object.is)

🚫
Bẫy thường gặp: Đưa object hoặc array literal tạo mới mỗi render vào dependency array ([{ id }], [options]) sẽ khiến effect chạy lại vô hạn vì JS so sánh object theo tham chiếu, không theo giá trị. Hãy tách thành các giá trị nguyên thủy ([id, page]) hoặc bọc bằng useMemo.

useMemo & useCallback — khi nào thực sự cần

Ghi nhớ giá trị/hàm dựa trên nguyên lý cache theo dependency của JS

memo-hooks.jsxMEMO
// useMemo — cache KẾT QUẢ tính toán, chỉ tính lại khi dependency đổi
const sortedList = useMemo(
  () => [...items].sort((a, b) => a.price - b.price),
  [items] // chỉ sort lại khi items đổi, không phải mỗi lần cha render
);

// useCallback — cache CHÍNH hàm đó (tránh tạo hàm mới mỗi render)
const handleSelect = useCallback(
  (id) => setSelectedId(id),
  [] // hàm không phụ thuộc biến ngoài -> giữ nguyên tham chiếu mãi mãi
);

// Quan trọng khi truyền xuống component đã bọc React.memo
<ItemRow onSelect={handleSelect} /> // nếu không useCallback, ItemRow luôn re-render
💡
Đừng lạm dụng: useMemo/useCallback tự nó cũng tốn chi phí (lưu cache, so sánh dependency). Chỉ nên dùng khi: (1) tính toán thực sự nặng, hoặc (2) giá trị/hàm được truyền xuống component con đã bọc React.memo và việc tạo mới mỗi render gây re-render thừa có thể đo lường được.

Custom Hooks — tái sử dụng logic JS

Một custom hook chỉ là hàm JS thường bắt đầu bằng "use" và gọi hook khác bên trong

useDebouncedValue.js — custom hook tái sử dụngHOOK
function useDebouncedValue(value, delay = 400) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer); // huỷ timer cũ mỗi khi value đổi trước khi hết delay
  }, [value, delay]);

  return debounced;
}

// Dùng lại ở bất kỳ component nào cần debounce
function SearchBox() {
  const [query, setQuery] = useState("");
  const debouncedQuery = useDebouncedValue(query, 300);
  // gọi API bằng debouncedQuery trong useEffect khác
}
✅
Quy tắc đặt tên: Custom hook luôn bắt đầu bằng use để React (và ESLint plugin) nhận diện được rằng nó phải tuân theo Rules of Hooks — chỉ gọi ở top-level, không gọi trong điều kiện/vòng lặp.

Debounce & Throttle bằng JS thuần

Giảm số lần gọi hàm khi user gõ nhanh, cuộn trang, resize cửa sổ

debounce-throttle.jsUTILS
// debounce — chỉ chạy sau khi ngừng gọi trong "delay" ms (search box, input validate)
function debounce(fn, delay = 300) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

// throttle — chạy tối đa 1 lần mỗi "limit" ms (scroll, resize, mousemove)
function throttle(fn, limit = 200) {
  let inThrottle = false;
  return (...args) => {
    if (!inThrottle) {
      fn(...args);
      inThrottle = true;
      setTimeout(() => (inThrottle = false), limit);
    }
  };
}

LocalStorage, JSON & Error Handling gọn

Lưu state đơn giản phía client và xử lý lỗi không làm crash cả app

useLocalStorage.jsSTORAGE
function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    try {
      const saved = localStorage.getItem(key);
      return saved ? JSON.parse(saved) : initialValue;
    } catch {
      return initialValue; // JSON hỏng hoặc localStorage bị chặn -> fallback an toàn
    }
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}
💡
Mẹo Error Boundary: try/catch chỉ bắt lỗi trong hàm đồng bộ/async gọi trực tiếp — nó không bắt được lỗi xảy ra khi render JSX. Muốn chặn lỗi render làm sập cả app, cần dùng Error Boundary (class component với componentDidCatch hoặc thư viện như react-error-boundary).

Vì sao component re-render & cách tránh

Hiểu gốc rễ bằng JS trước khi vội thêm memo khắp nơi

3 nguyên nhân khiến component render lại
1

State của chính nó đổi

Gọi setState với giá trị khác giá trị hiện tại (so sánh Object.is) sẽ luôn kích hoạt render lại — đây là hành vi mong muốn.

2

Component cha render lại

Mặc định, khi cha render, mọi component con đều render theo — kể cả khi props không đổi. Đây là nguyên nhân re-render thừa phổ biến nhất.

// Child chỉ render lại khi props thực sự đổi giá trị (shallow compare)
const ItemRow = React.memo(function ItemRow({ item, onSelect }) {

function ItemList({ items }) {

Virtualization cho danh sách dài

Chỉ render các phần tử đang hiển thị trong viewport bằng cách tính toán JS

Khi danh sách có hàng nghìn phần tử (bảng dữ liệu, feed, chat log), render toàn bộ DOM node cùng lúc sẽ làm trình duyệt ì. Virtualization tính toán bằng JS xem phần tử nào đang nằm trong vùng nhìn thấy (dựa trên scrollTop và chiều cao mỗi item), chỉ render đúng số đó — phần còn lại được thay bằng khoảng trống (padding) để giữ đúng chiều cao scrollbar.

Search box: debounce + AbortController

Gộp tất cả kỹ thuật đã học vào 1 component thực tế

SearchBox.jsxFULL EXAMPLE
function SearchBox() {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState([]);
  const [loading, setLoading] = useState(false);
  const debouncedQuery = useDebouncedValue(query, 350);

  useEffect(() => {
    if (!debouncedQuery.trim()) {
      setResults([]);
      return;
    }
    const controller = new AbortController();

    (async () => {
      try {
        setLoading(true);
        const res = await fetch(
          `/api/search?q=${encodeURIComponent(debouncedQuery)}`,
          { signal: controller.signal }
        );
        const data = await res.json();
        setResults(data);
      } catch (err) {
        if (err.name !== "AbortError") console.error(err);
      } finally {
        setLoading(false);
      }
    })();

    return () => controller.abort(); // huỷ request cũ nếu query đổi trước khi kịp trả về
  }, [debouncedQuery]);

  return (
    <div>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      {loading && <Spinner />}
      <ul>
        {results.map((r) => <li key={r.id}>{r.title}</li>)}
      </ul>
    </div>
  );
}
✅
Component này kết hợp: debounce (giảm số request khi gõ nhanh), AbortController (huỷ request cũ tránh race condition — kết quả cũ trả về sau đè lên kết quả mới), và try/catch/finally để quản lý trạng thái loading rõ ràng.

Infinite scroll với IntersectionObserver

API JS gốc của trình duyệt, không cần lắng nghe sự kiện scroll thủ công

useInfiniteScroll.jsOBSERVER
function useInfiniteScroll(onLoadMore) {
  const sentinelRef = useRef(null);

  useEffect(() => {
    const node = sentinelRef.current;
    if (!node) return;

    const observer = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting) onLoadMore(); // sentinel lọt vào viewport -> tải thêm trang
      },
      { rootMargin: "200px" } // tải sớm trước khi chạm đáy 200px
    );

    observer.observe(node);
    return () => observer.disconnect(); // cleanup — tránh leak observer khi unmount
  }, [onLoadMore]);

  return sentinelRef;
}

// Sử dụng trong danh sách feed
function Feed() {
  const [posts, setPosts] = useState([]);
  const loadMore = useCallback(() => fetchNextPage().then((p) => setPosts((prev) => [...prev, ...p])), []);
  const sentinelRef = useInfiniteScroll(loadMore);

  return (
    <>
      {posts.map((p) => <PostCard key={p.id} post={p} />)}
      <div ref={sentinelRef} /> {/* phần tử "cảm biến" vô hình để theo dõi */}
    </>
  );
}
💡
Vì sao tốt hơn onScroll: IntersectionObserver chạy bất đồng bộ trên luồng riêng của trình duyệt, không kích hoạt liên tục hàng chục lần mỗi giây như sự kiện scroll — nhẹ hơn nhiều và không cần tự viết throttle.
