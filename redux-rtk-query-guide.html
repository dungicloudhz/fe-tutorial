Redux, Redux Toolkit & RTK Query là gì?

Khái niệm cốt lõi, vì sao cần state quản lý toàn cục, kiến trúc tổng thể

Vấn đề Redux giải quyết

Khi ứng dụng lớn lên, nhiều component ở xa nhau cần chia sẻ cùng một state (giỏ hàng, user đăng nhập, theme...). Truyền props qua nhiều tầng ("prop drilling") trở nên cồng kềnh. Redux tạo ra một kho state duy nhất (store) mà mọi component đọc/ghi trực tiếp, không cần truyền qua props.

🏬
Store — 1 nguồn sự thật
Toàn bộ state của app nằm trong 1 object JS duy nhất, dễ debug, dễ theo dõi lịch sử thay đổi.
🍰
Redux Toolkit (RTK)
Bộ công cụ chính thức, viết Redux ít boilerplate hơn — createSlice, configureStore có sẵn.
🛠️
RTK Query
Lớp gọi API tích hợp sẵn trong RTK — tự sinh hook, tự cache, tự loading/error state.

Tạo Store với configureStore

Gộp mọi slice + api middleware vào 1 store duy nhất

app/store.jsSTORE
import { configureStore } from "@reduxjs/toolkit";
import todosReducer from "../features/todos/todosSlice";
import { apiSlice } from "../services/apiSlice";

export const store = configureStore({
  reducer: {
    todos: todosReducer,                        // state.todos
    [apiSlice.reducerPath]: apiSlice.reducer, // state.api — cache của RTK Query
  },
  middleware: (getDefault) =>
    getDefault().concat(apiSlice.middleware), // bắt buộc — kích hoạt cache/refetch tự động
});
main.jsx — bọc app bằng ProviderPROVIDER
import { Provider } from "react-redux";
import { store } from "./app/store";
import App from "./App";

ReactDOM.createRoot(document.getElementById("root")).render(
  <Provider store={store}>
    <App />
  </Provider>
);

createSlice — Actions & Reducers

1 hàm định nghĩa cả state ban đầu, reducer, và tự sinh action creators

features/todos/todosSlice.jsSLICE
import { createSlice, nanoid } from "@reduxjs/toolkit";

const todosSlice = createSlice({
  name: "todos",
  initialState: { items: [], filter: "all" },
  reducers: {
    todoAdded: (state, action) => {
      // RTK dùng Immer bên trong — "mutate" trực tiếp vẫn AN TOÀN
      state.items.push({ id: nanoid(), text: action.payload, done: false });
    },
    todoToggled: (state, action) => {
      const todo = state.items.find((t) => t.id === action.payload);
      if (todo) todo.done = !todo.done;
    },
    filterChanged: (state, action) => {
      state.filter = action.payload;
    },
  },
});

// Action creators được TỰ SINH từ tên trong "reducers"
export const { todoAdded, todoToggled, filterChanged } = todosSlice.actions;
export default todosSlice.reducer;
  • createSlice tự sinh action creators và action types từ tên hàm trong reducers — không phải viết tay như Redux cổ điển.
  • Nhờ thư viện Immer tích hợp sẵn, bạn được phép viết code như đang mutate trực tiếp (state.items.push(...)) — RTK tự chuyển thành cập nhật immutable phía sau.
  • action.payload là dữ liệu bạn truyền khi dispatch: dispatch(todoAdded("Mua sữa")) → payload = "Mua sữa".

useSelector & useDispatch

2 hook chính để đọc và ghi state từ bất kỳ component nào

TodoList.jsxHOOK
import { useSelector, useDispatch } from "react-redux";
import { todoToggled, filterChanged } from "./todosSlice";

function TodoList() {
  const dispatch = useDispatch();

  // useSelector đọc 1 phần state — component chỉ render lại khi phần này đổi
  const filter = useSelector((state) => state.todos.filter);
  const items = useSelector((state) => state.todos.items);

  const visible = items.filter((t) =>
    filter === "all" ? true : filter === "done" ? t.done : !t.done
  );

  return (
    <ul>
      {visible.map((t) => (
        <li key={t.id} onClick={() => dispatch(todoToggled(t.id))}>
          {t.done ? "✅" : "⬜"} {t.text}
        </li>
      ))}
    </ul>
  );
}
⚠️
Tối ưu re-render: Gọi nhiều useSelector nhỏ (mỗi cái chọn 1 field) thay vì 1 selector trả cả object lớn — useSelector chỉ render lại khi giá trị được chọn thực sự đổi (so sánh bằng ===).

Xử lý bất đồng bộ với createAsyncThunk

Cách gọi API "kiểu Redux cổ điển" — nên biết trước khi chuyển sang RTK Query

features/todos/todosSlice.js — thêm thunkTHUNK
import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";

// Thunk: hàm async, tự động dispatch pending/fulfilled/rejected
export const fetchTodos = createAsyncThunk("todos/fetchTodos", async () => {
  const res = await fetch("/api/todos");
  return await res.json(); // giá trị trả về → action.payload ở "fulfilled"
});

const todosSlice = createSlice({
  name: "todos",
  initialState: { items: [], status: "idle" },
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(fetchTodos.pending, (state) => { state.status = "loading"; })
      .addCase(fetchTodos.fulfilled, (state, action) => {
        state.status = "succeeded";
        state.items = action.payload;
      })
      .addCase(fetchTodos.rejected, (state) => { state.status = "failed"; });
  },
});
📝
createAsyncThunk hoạt động tốt nhưng bạn phải tự viết loading/error state, tự cache, tự tránh gọi trùng lặp. Đây chính xác là lý do RTK Query ra đời — phần tiếp theo sẽ thay thế phần lớn code này bằng vài dòng khai báo.

createApi & Endpoints

Khai báo 1 lần — RTK Query tự lo cache, loading, refetch

services/apiSlice.jsAPI SLICE
import { createApi, fetchBaseQuery } from "@reduxjs/toolkit/query/react";

export const apiSlice = createApi({
  reducerPath: "api",
  baseQuery: fetchBaseQuery({ baseUrl: "/api" }),
  tagTypes: ["Post"], // khai báo trước loại "thẻ" dùng để cache/invalidate
  endpoints: (builder) => ({
    getPosts: builder.query({
      query: () => "/posts",                     // GET /api/posts
      providesTags: ["Post"],
    }),
    getPostById: builder.query({
      query: (id) => `/posts/` + id,               // GET /api/posts/:id
      providesTags: (result, error, id) => [{ type: "Post", id }],
    }),
    addPost: builder.mutation({
      query: (newPost) => ({ url: "/posts", method: "POST", body: newPost }),
      invalidatesTags: ["Post"],          // tự động refetch getPosts sau khi thêm
    }),
  }),
});

// RTK Query tự sinh hooks từ tên endpoint (getPosts → useGetPostsQuery)
export const { useGetPostsQuery, useGetPostByIdQuery, useAddPostMutation } = apiSlice;
  • builder.query — dùng cho đọc dữ liệu (GET), tự cache theo tham số truyền vào.
  • builder.mutation — dùng cho ghi dữ liệu (POST/PUT/DELETE), không tự cache.
  • providesTags/invalidatesTags là cơ chế cache thông minh — chi tiết ở phần Caching & Tags bên dưới.

Hooks tự sinh — dùng trong component

Không cần useEffect, không cần useState riêng cho loading/error

Query hook — đọc dữ liệu
PostList.jsxQUERY HOOK
import { useGetPostsQuery } from "../services/apiSlice";

function PostList() {
  // Chỉ 1 dòng thay cho: useState + useEffect + fetch + try/catch
  const {
    data: posts,
    isLoading,
    isError,
    error,
    refetch,
  } = useGetPostsQuery();

  if (isLoading) return <p>Đang tải...</p>;
  if (isError) return <p>Lỗi: {error.message} <button onClick={refetch}>Thử lại</button></p>;

  return <ul>{posts.map((p) => <li key={p.id}>{p.title}</li>)}</ul>;
}
Mutation hook — ghi dữ liệu
AddPostForm.jsxMUTATION HOOK
import { useState } from "react";
import { useAddPostMutation } from "../services/apiSlice";

function AddPostForm() {
  const [title, setTitle] = useState("");
  // mutation hook trả về [hàm trigger, trạng thái request]
  const [addPost, { isLoading }] = useAddPostMutation();

  async function handleSubmit(e) {
    e.preventDefault();
    await addPost({ title }).unwrap(); // unwrap() ném lỗi thật nếu request fail
    setTitle("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={title} onChange={(e) => setTitle(e.target.value)} />
      <button disabled={isLoading}>{isLoading ? "Đang lưu..." : "Đăng bài"}</button>
    </form>
  );
}
Field trả vềÝ nghĩa
dataDữ liệu trả về sau khi request thành công
isLoadingĐang gọi request lần đầu tiên (chưa có cache)
isFetchingĐang gọi lại request (kể cả khi đã có cache cũ để hiển thị)
isError / errorRequest thất bại và thông tin lỗi

RTK QUERY

Caching & Tags — cơ chế "linh hồn" của RTK Query

providesTags / invalidatesTags giúp dữ liệu luôn tự đồng bộ

Nguyên lý hoạt động
1

Query gắn tag khi lấy dữ liệu

getPosts khai báo providesTags: ["Post"] — nghĩa là kết quả này "thuộc về" nhãn Post. RTK Query lưu cache và nhớ mối liên kết này.

2

Mutation khai báo tag nào bị "vô hiệu"

addPost khai báo invalidatesTags: ["Post"] — báo rằng sau khi mutation này chạy xong, mọi cache mang nhãn Post đã lỗi thời.

3

RTK Query tự động refetch

Bất kỳ component nào đang dùng useGetPostsQuery() sẽ tự động gọi lại API và cập nhật UI — bạn không cần tự gọi refetch() hay quản lý state đồng bộ thủ công.

Tag theo ID — invalidate chính xác, tránh refetch thừa
services/apiSlice.js — tag chi tiết theo idTAGS
endpoints: (builder) => ({
  getPosts: builder.query({
    query: () => "/posts",
    // mỗi post trong danh sách + 1 tag chung "LIST"
    providesTags: (result = []) => [
      ...result.map(({ id }) => ({ type: "Post", id })),
      { type: "Post", id: "LIST" },
    ],
  }),
  updatePost: builder.mutation({
    query: ({ id, ...patch }) => ({ url: `/posts/` + id, method: "PATCH", body: patch }),
    // chỉ invalidate ĐÚNG post vừa sửa — không refetch cả danh sách
    invalidatesTags: (result, error, { id }) => [{ type: "Post", id }],
  }),
}),
💡
Dùng tag theo id cụ thể thay vì 1 tag chung cho mọi thứ — giúp chỉ những component thật sự liên quan mới bị refetch, tránh gọi API thừa và giữ app mượt hơn khi dữ liệu lớn.

Optimistic Updates

Cập nhật UI ngay lập tức, không đợi server phản hồi

services/apiSlice.js — onQueryStartedOPTIMISTIC
toggleTodo: builder.mutation({
  query: (id) => ({ url: `/todos/` + id + `/toggle`, method: "PATCH" }),

  async onQueryStarted(id, { dispatch, queryFulfilled }) {
    // 1. Cập nhật cache NGAY LẬP TỨC, trước khi server trả lời
    const patch = dispatch(
      apiSlice.util.updateQueryData("getTodos", undefined, (draft) => {
        const todo = draft.find((t) => t.id === id);
        if (todo) todo.done = !todo.done;
      })
    );
    try {
      await queryFulfilled; // 2. Đợi server xác nhận thật sự
    } catch {
      patch.undo(); // 3. Nếu server lỗi → tự động rollback UI về trạng thái cũ
    }
  },
}),
✅
Optimistic update cho cảm giác app "phản hồi tức thì" (như tick checkbox, like bài viết) — RTK Query lo sẵn cơ chế rollback nếu request thất bại, bạn không cần tự viết logic phục hồi state.

Đặt Provider trong App Router

Redux store chỉ tồn tại phía client — cần "use client" đúng chỗ

1. Tạo Provider component riêng (bắt buộc "use client")
app/StoreProvider.js"use client"
"use client";

import { useRef } from "react";
import { Provider } from "react-redux";
import { makeStore } from "./store";

export default function StoreProvider({ children }) {
  // Mỗi request/tab tạo 1 store MỚI — tránh rò rỉ dữ liệu giữa các user (SSR)
  const storeRef = useRef();
  if (!storeRef.current) {
    storeRef.current = makeStore();
  }
  return <Provider store={storeRef.current}>{children}</Provider>;
}
app/store.js — dùng factory function thay vì export trực tiếpSTORE FACTORY
import { configureStore } from "@reduxjs/toolkit";
import todosReducer from "../features/todos/todosSlice";
import { apiSlice } from "../services/apiSlice";

// Factory — mỗi lần gọi tạo 1 store mới, KHÔNG export singleton như React thuần
export const makeStore = () =>
  configureStore({
    reducer: {
      todos: todosReducer,
      [apiSlice.reducerPath]: apiSlice.reducer,
    },
    middleware: (getDefault) => getDefault().concat(apiSlice.middleware),
  });
2. Gắn vào Root Layout
app/layout.jsLAYOUT
import StoreProvider from "./StoreProvider";

export default function RootLayout({ children }) {
  return (
    <html lang="vi">
      <body>
        <StoreProvider>{children}</StoreProvider>
      </body>
    </html>
  );
}
🚫
Sai lầm thường gặp: export const store = configureStore(...) theo kiểu singleton (như React thuần) sẽ chia sẻ 1 store giữa nhiều request server trong môi trường Next.js SSR — gây rò rỉ dữ liệu giữa các user. Luôn dùng factory function makeStore() + tạo mới trong useRef.

Ví dụ: Todo App với Redux Toolkit

Slice + Store + Component — chạy được ngay trong dự án React/Vite

features/todos/todosSlice.jsSLICE
import { createSlice, nanoid } from "@reduxjs/toolkit";

const todosSlice = createSlice({
  name: "todos",
  initialState: { items: [], filter: "all" },
  reducers: {
    todoAdded: {
      reducer(state, action) { state.items.push(action.payload); },
      prepare(text) { return { payload: { id: nanoid(), text, done: false } }; },
    },
    todoToggled(state, action) {
      const t = state.items.find((x) => x.id === action.payload);
      if (t) t.done = !t.done;
    },
    todoRemoved(state, action) {
      state.items = state.items.filter((t) => t.id !== action.payload);
    },
    filterChanged(state, action) { state.filter = action.payload; },
  },
});

export const { todoAdded, todoToggled, todoRemoved, filterChanged } = todosSlice.actions;
export default todosSlice.reducer;
TodoApp.jsxCOMPONENT
import { useState } from "react";
import { useSelector, useDispatch } from "react-redux";
import { todoAdded, todoToggled, todoRemoved, filterChanged } from "./features/todos/todosSlice";

function TodoApp() {
  const dispatch = useDispatch();
  const items = useSelector((s) => s.todos.items);
  const filter = useSelector((s) => s.todos.filter);
  const [text, setText] = useState("");

  const visible = items.filter((t) =>
    filter === "all" ? true : filter === "done" ? t.done : !t.done
  );

  return (
    <div>
      <input value={text} onChange={(e) => setText(e.target.value)}
        onKeyDown={(e) => {
          if (e.key === "Enter" && text.trim()) {
            dispatch(todoAdded(text));
            setText("");
          }
        }} />

      <div>
        {["all", "active", "done"].map((f) => (
          <button key={f} onClick={() => dispatch(filterChanged(f))}>{f}</button>
        ))}
      </div>

      <ul>
        {visible.map((t) => (
          <li key={t.id}>
            <span onClick={() => dispatch(todoToggled(t.id))}
              style={{ textDecoration: t.done ? "line-through" : "none" }}>
              {t.text}
            </span>
            <button onClick={() => dispatch(todoRemoved(t.id))}>Xoá</button>
          </li>
        ))}
      </ul>
    </div>
  );
}

export default TodoApp;
📝
Điểm học được: mẫu prepare callback giúp tạo id ngẫu nhiên (nanoid) ngay trong action creator thay vì trong component; state UI cục bộ (text đang gõ) vẫn dùng useState bình thường — chỉ state cần chia sẻ mới đưa vào Redux.

Ví dụ: Next.js Blog với RTK Query

Danh sách bài viết + like button, cache tự động đồng bộ qua tags

1. Định nghĩa API
services/postsApi.jsAPI SLICE
import { createApi, fetchBaseQuery } from "@reduxjs/toolkit/query/react";

export const postsApi = createApi({
  reducerPath: "postsApi",
  baseQuery: fetchBaseQuery({ baseUrl: "/api" }),
  tagTypes: ["Post"],
  endpoints: (builder) => ({
    getPosts: builder.query({
      query: () => "/posts",
      providesTags: (r = []) => [...r.map(({ id }) => ({ type: "Post", id })), { type: "Post", id: "LIST" }],
    }),
    likePost: builder.mutation({
      query: (id) => ({ url: `/posts/` + id + `/like`, method: "POST" }),
      invalidatesTags: (r, e, id) => [{ type: "Post", id }],
    }),
  }),
});

export const { useGetPostsQuery, useLikePostMutation } = postsApi;
2. Client Component hiển thị danh sách + nút like
app/blog/PostList.jsCLIENT COMPONENT
"use client";

import { useGetPostsQuery, useLikePostMutation } from "../../services/postsApi";

export default function PostList() {
  const { data: posts, isLoading } = useGetPostsQuery();
  const [likePost] = useLikePostMutation();

  if (isLoading) return <p>Đang tải bài viết...</p>;

  return (
    <ul>
      {posts.map((p) => (
        <li key={p.id}>
          p.title — ❤️ {p.likes}
          <button onClick={() => likePost(p.id)}>Thích</button>
        </li>
      ))}
    </ul>
  );
}
