OVERVIEW

Bản đồ HTML & CSS — hai nền tảng của mọi trang web

HTML lo về nội dung & cấu trúc, CSS lo về trình bày & bố cục — hiểu rõ vai trò từng bên trước khi học sâu

HTML và CSS làm việc gì, cho ai?

HTML (HyperText Markup Language) là ngôn ngữ đánh dấu dùng để mô tả nội dung và cấu trúc của trang: đâu là tiêu đề, đâu là đoạn văn, đâu là danh sách, đâu là ảnh. CSS (Cascading Style Sheets) quyết định trang trông như thế nào: màu sắc, khoảng cách, font chữ, bố cục responsive trên các kích thước màn hình khác nhau. Trình duyệt đọc HTML để dựng cây DOM, rồi áp CSS lên cây đó để vẽ ra giao diện cuối cùng.

Cấu trúc tài liệu HTML

Bộ khung tối thiểu mà mọi trang HTML đều cần có

Khung HTML chuẩn
index.htmlSTRUCTURE
<!DOCTYPE html> <!-- báo cho trình duyệt đây là HTML5 -->
<html lang="vi">
<head>
  <meta charset="UTF-8"> <!-- bảng mã ký tự, cần cho tiếng Việt -->
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Trang của tôi</title> <!-- hiện trên tab trình duyệt -->
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <!-- toàn bộ nội dung hiển thị nằm trong body -->
  <h1>Xin chào!</h1>
  <p>Đây là đoạn văn đầu tiên.</p>
  <script src="script.js"></script>
</body>
</html>
ThẻVai trò
<!DOCTYPE html>Khai báo phiên bản HTML5, luôn đặt ở dòng đầu tiên
<html>Thẻ gốc bao bọc toàn bộ tài liệu, nên có lang để hỗ trợ SEO/screen reader
<head>Chứa metadata: title, charset, viewport, link CSS — không hiển thị trực tiếp
<body>Chứa toàn bộ nội dung người dùng nhìn thấy trên trang
<meta viewport>Bắt buộc để trang responsive đúng trên điện thoại
✅
Ghi nhớ: Đặt <script> ở cuối <body> (hoặc dùng defer) để JS không chặn việc render HTML — trang sẽ hiện nội dung nhanh hơn.

Semantic HTML5

Dùng thẻ đúng ý nghĩa thay vì nhồi toàn <div>

Vì sao cần semantic?

Trước HTML5, người ta hay dùng <div id="header">, <div id="nav">... Trình duyệt/máy tìm kiếm/screen reader không hiểu đó là gì ngoài "1 khối chung chung". HTML5 thêm các thẻ có ý nghĩa (semantic) để khai báo rõ vai trò từng vùng — giúp SEO tốt hơn, accessibility tốt hơn, và code dễ đọc hơn.

layout.html — bố cục trang bằng thẻ semanticSEMANTIC
<body>
  <header>
    <h1>Tên trang</h1>
    <nav> <!-- menu điều hướng chính -->
      <ul><li><a href="/">Trang chủ</a></li></ul>
    </nav>
  </header>

  <main> <!-- nội dung chính, chỉ 1 thẻ main / trang -->
    <article> <!-- nội dung độc lập, có thể đứng riêng: bài viết, sản phẩm -->
      <h2>Tiêu đề bài viết</h2>
      <p>Nội dung...</p>
    </article>

    <section> <!-- một nhóm nội dung liên quan, thường có heading riêng -->
      <h2>Bình luận</h2>
    </section>

    <aside> <!-- nội dung phụ, liên quan gián tiếp: sidebar, quảng cáo -->
      <p>Bài viết liên quan</p>
    </aside>
  </main>

  <footer>
    <p>© 2026 Công ty ABC</p>
  </footer>
</body>
ThẻDùng cho
<header>Phần đầu trang hoặc đầu 1 section (logo, tiêu đề, nav)
<nav>Khối chứa các liên kết điều hướng chính
<main>Nội dung chính, duy nhất, không lặp lại (không chứa nav/footer)
<article>Nội dung có thể đứng độc lập, tái sử dụng được: bài blog, sản phẩm
<section>Một nhóm nội dung theo chủ đề, thường đi kèm heading riêng
<aside>Nội dung phụ, không phải trọng tâm: sidebar, ghi chú
<footer>Phần cuối trang hoặc cuối 1 section: bản quyền, liên kết phụ

data-*, ARIA — giúp trang dễ tương tác hơn với JS và với người khuyết tật

data-* — gắn dữ liệu tùy biến cho JavaScript
data-attr.htmlDATA-*
<button data-product-id="128" data-action="add-to-cart">
  Thêm vào giỏ
</button>

<script>
document.querySelector("button").addEventListener("click", e => {
  // đọc data-* qua .dataset (camelCase)
  console.log(e.target.dataset.productId); // "128"
});
</script>
ARIA — hỗ trợ screen reader
aria.htmlARIA
<!-- nút chỉ có icon: cần aria-label mô tả chức năng -->
<button aria-label="Đóng thông báo">✕</button>

<!-- báo trạng thái mở/đóng cho menu thả xuống -->
<button aria-expanded="false" aria-controls="menu">Menu</button>
<ul id="menu" hidden> ... </ul>

<!-- vùng cập nhật động (thông báo lỗi form) -> screen reader tự đọc khi đổi -->
<div role="alert" aria-live="polite">Email không hợp lệ</div>
📌
Quy tắc số 1 của ARIA: "No ARIA is better than bad ARIA". Luôn ưu tiên thẻ HTML semantic có sẵn (<button> thay vì <div onclick>) — chỉ thêm ARIA khi thẻ chuẩn không đủ diễn tả.

Cách nhúng CSS & Selector

3 cách gắn CSS vào HTML, và cách "chọn" đúng phần tử cần style

3 cách nhúng CSS
nhung-css.html3 CÁCH
<!-- 1. External: file .css riêng — CÁCH KHUYẾN NGHỊ -->
<link rel="stylesheet" href="style.css">

<!-- 2. Internal: viết trong thẻ style ở head -->
<style>
  p { color: navy; }
</style>

<!-- 3. Inline: viết trực tiếp trên thẻ — tránh dùng, khó bảo trì -->
<p style="color: navy;">Xin chào</p>
Các loại Selector thường dùng
style.cssSELECTOR
/* Selector theo thẻ */
p { color: #333; }

/* Selector theo class — dùng .tên-class, tái sử dụng nhiều nơi */
.btn-primary { background: #38bdf8; }

/* Selector theo id — dùng #id, chỉ nên có 1 phần tử / trang */
#header { height: 64px; }

/* Selector con trực tiếp (>) và cháu (khoảng trắng) */
.card > h3 { margin-top: 0; }
.card p { color: gray; }

/* Selector nhiều điều kiện (không có khoảng trắng = AND) */
input.error { border-color: red; }

/* Selector theo thuộc tính */
input[type="email"] { border-radius: 6px; }

/* Nhóm nhiều selector cùng style (phẩy) */
h1, h2, h3 { font-family: "Be Vietnam Pro", sans-serif; }
⚠️
Độ ưu tiên (specificity): inline style > id > class/thuộc tính > thẻ. Khi 2 rule cùng áp dụng, rule "cụ thể hơn" thắng — đây là lý do lạm dụng id hay !important khiến CSS khó bảo trì về sau.

Box Model

Nền tảng quan trọng nhất: mọi phần tử đều là một "hộp"

4 lớp của một hộp CSS
margin
border
padding
content

Từ trong ra ngoài: content (nội dung thật — chữ, ảnh) → padding (khoảng đệm bên trong, giữa nội dung và viền) → border (đường viền) → margin (khoảng cách với phần tử bên ngoài). Tổng chiều rộng hiển thị = content + padding + border + margin.

box-model.cssBOX MODEL
.card {
  width: 300px;
  padding: 20px;          /* đệm 4 phía */
  border: 1px solid #ddd;
  margin: 16px auto;    /* trên/dưới 16px, trái/phải tự căn giữa */

  /* box-sizing: border-box -> width đã BAO GỒM padding + border
     -> hộp không "phình to" ngoài ý muốn khi thêm padding. NÊN đặt mặc định! */
  box-sizing: border-box;
}

/* Reset kinh điển: áp border-box cho MỌI phần tử */
*, *::before, *::after {
  box-sizing: border-box;
}
✅
Luôn đặt box-sizing: border-box global. Với content-box (mặc định), thêm padding sẽ làm hộp to hơn width đã khai báo — gây lệch layout khó hiểu. border-box tính padding/border vào trong width, dễ đoán kích thước hơn nhiều.

blockChiếm hết chiều ngang, luôn xuống dòng mới (div, p, h1...)
inlineChỉ chiếm đúng phần nội dung, nằm cùng dòng, không set được width/height (span, a, strong...)
inline-blockNằm cùng dòng như inline nhưng set được width/height như block
flexBiến phần tử thành flex container — xem mục Flexbox
gridBiến phần tử thành grid container — xem mục Grid
noneẨn hoàn toàn, không chiếm chỗ (khác visibility:hidden vẫn chiếm chỗ)
position — đưa phần tử ra khỏi luồng
position.cssPOSITION
/* static: mặc định, top/left/right/bottom vô tác dụng */
.normal { position: static; }

/* relative: vẫn chiếm chỗ cũ, dịch chuyển SO VỚI vị trí gốc của chính nó */
.shift { position: relative; top: 4px; }

/* absolute: thoát khỏi luồng, định vị theo tổ tiên gần nhất có position != static */
.badge {
  position: absolute;
  top: 8px; right: 8px;
}
.card { position: relative; } /* -> .badge định vị theo .card */

/* fixed: ghim theo viewport, không di chuyển khi cuộn trang */
.back-to-top { position: fixed; bottom: 20px; right: 20px; }

/* sticky: dính lại khi cuộn tới ngưỡng, rồi thoát khi cuộn qua khỏi cha */
.table-header { position: sticky; top: 0; }
📌
Ghi nhớ cặp đôi: position: absolute luôn cần một phần tử cha có position: relative (hoặc absolute/fixed) để làm "mốc" — nếu không nó sẽ định vị theo toàn bộ trang (<html>).

Flexbox

Bố cục 1 chiều (hàng hoặc cột) — công cụ dùng nhiều nhất trong CSS hiện đại

Flex container & flex item
flexbox.cssFLEXBOX
.navbar {
  display: flex;                 /* bật flex cho container */
  flex-direction: row;       /* row (mặc định) | column */
  justify-content: space-between; /* căn theo trục CHÍNH (ngang nếu row) */
  align-items: center;      /* căn theo trục PHỤ (dọc nếu row) */
  gap: 16px;                /* khoảng cách giữa các item, không cần margin thủ công */
  flex-wrap: wrap;          /* cho phép xuống dòng khi không đủ chỗ */
}

.navbar .logo { flex: 0 0 auto; } /* không co giãn, giữ kích thước tự nhiên */
.navbar .search { flex: 1; }       /* chiếm hết khoảng trống còn lại */
Thuộc tínhGiá trị hay dùngTác dụng
justify-contentflex-start / center / space-between / space-aroundCăn item theo trục chính (thường là ngang)
align-itemsflex-start / center / stretchCăn item theo trục phụ (thường là dọc)
flex: 1tương đương flex-grow:1Item giãn ra chiếm hết không gian thừa
flex-wrap: wrap—Cho item tự xuống hàng thay vì bị ép co lại
✅
Mẹo căn giữa tuyệt đối: display:flex; justify-content:center; align-items:center; trên phần tử cha là cách nhanh nhất để căn giữa cả ngang lẫn dọc bất kỳ nội dung con nào — thay thế hoàn toàn kỹ thuật margin âm/absolute thời xưa.

CSS Grid

Bố cục 2 chiều (hàng và cột cùng lúc) — mạnh nhất cho layout tổng thể trang

Grid container cơ bản
grid.cssGRID
.gallery {
  display: grid;
  grid-template-columns: repeat(3, 1fr); /* 3 cột bằng nhau */
  gap: 16px;
}

/* Layout trang kinh điển: header full-width, sidebar + content, footer full-width */
.page {
  display: grid;
  grid-template-columns: 240px 1fr;   /* cột 1 cố định 240px, cột 2 chiếm phần còn lại */
  grid-template-areas:
    "header header"
    "sidebar content"
    "footer footer";
}
.header  { grid-area: header; }
.sidebar { grid-area: sidebar; }
.content { grid-area: content; }
.footer  { grid-area: footer; }

/* auto-fit + minmax: số cột tự co giãn theo độ rộng màn hình, không cần media query */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 14px;
}
💡
Flexbox hay Grid? Bố cục 1 chiều (thanh menu, nhóm nút, danh sách card cuộn ngang) → Flexbox. Bố cục 2 chiều (toàn bộ khung trang, gallery ảnh nhiều hàng nhiều cột) → Grid. Thực tế hầu hết dự án dùng cả hai kết hợp.

Responsive & Media Query

Làm trang hiển thị tốt trên mọi kích thước màn hình

Mobile-first với media query
responsive.cssMEDIA QUERY
/* Mobile-first: style mặc định dành cho màn hình NHỎ trước */
.cards {
  display: grid;
  grid-template-columns: 1fr;      /* mobile: 1 cột */
  gap: 12px;
}

/* min-width: 768px -> áp dụng khi màn hình RỘNG HƠN mốc tablet */
@media (min-width: 768px) {
  .cards { grid-template-columns: repeat(2, 1fr); } /* tablet: 2 cột */
}

@media (min-width: 1024px) {
  .cards { grid-template-columns: repeat(4, 1fr); } /* desktop: 4 cột */
}
Breakpoint phổ biếnThiết bị
< 576pxĐiện thoại
576px – 768pxĐiện thoại lớn / tablet dọc
768px – 1024pxTablet ngang
> 1024pxDesktop
✅
Vì sao "mobile-first"? Viết CSS mặc định cho mobile rồi min-width mở rộng dần lên desktop giúp CSS gọn hơn (đa số người dùng lướt web bằng điện thoại) và tránh phải "ghi đè" hàng loạt style desktop bằng max-width.

Transition & Animation

Tạo chuyển động mượt mà mà không cần JavaScript

Transition — chuyển đổi mượt giữa 2 trạng thái
transition.cssTRANSITION
.btn {
  background: #38bdf8;
  transform: scale(1);
  /* thuộc-tính | thời-gian | kiểu-easing */
  transition: background .2s ease, transform .2s ease;
}
.btn:hover {
  background: #0ea5e9;
  transform: scale(1.04);   /* phóng to nhẹ khi hover */
}
Animation — chuyển động phức tạp, nhiều bước, tự chạy
animation.cssANIMATION
/* khai báo các bước (keyframes) bằng % thời gian */
@keyframes pulse {
  0%, 100% { opacity: 1; transform: scale(1); }
  50%       { opacity: .5; transform: scale(.85); }
}

.dot {
  animation: pulse 2s ease-in-out infinite;
  /* tên-keyframes | thời-lượng | easing | số-lần-lặp (infinite = vô hạn) */
}
⚠️
Hiệu năng: Ưu tiên animate transform và opacity — 2 thuộc tính này được GPU tăng tốc, không gây "reflow" (tính lại layout). Animate width, top, margin trực tiếp dễ gây giật lag trên máy yếu.

CSS Custom Properties (biến CSS)
variables.cssVAR
/* khai báo biến ở :root -> dùng được toàn trang */
:root {

  --radius: 10px;

Transform, z-index & Overflow

Xoay/di chuyển phần tử, xử lý lớp chồng và tràn nội dung

transform — biến đổi hình học không ảnh hưởng layout
transform.cssTRANSFORM
.avatar { transform: rotate(8deg); }              /* xoay */
.card:hover { transform: translateY(-4px); }   /* dịch lên, hiệu ứng "nổi" */
.zoom:hover { transform: scale(1.1); }        /* phóng to */

/* căn giữa tuyệt đối kinh điển khi không dùng flex được */
.modal {
  position: absolute;
  top: 50%; left: 50%;
  transform: translate(-50%, -50%); /* lùi lại đúng nửa kích thước chính nó */
}
z-index — thứ tự chồng lớp
z-index.cssZ-INDEX
/* z-index chỉ có tác dụng khi position khác static */
.dropdown  { position: absolute; z-index: 10; }
.modal-overlay { position: fixed;  z-index: 100; } /* số cao hơn -> nổi lên trên */
📌
Mẹo quản lý z-index: Trong dự án lớn, khai báo sẵn các mốc bằng biến CSS (--z-dropdown: 10; --z-modal: 100; --z-toast: 1000;) thay vì đoán số ngẫu nhiên — tránh tình trạng "chiến tranh z-index" ngày càng tăng.

Best Practice & lỗi thường gặp

Những điều nên làm ngay từ đầu, và lỗi người mới hay mắc

Checklist khi bắt đầu 1 trang mới
1

Reset box-sizing & margin mặc định

Thêm * { box-sizing: border-box; margin: 0; padding: 0; } ở đầu file CSS để tránh khác biệt mặc định giữa các trình duyệt.

2

Dùng thẻ semantic thay vì toàn <div>

header/nav/main/section/footer giúp SEO và accessibility tốt hơn mà gần như không tốn thêm công sức.

3

Viết CSS theo hướng mobile-first

Style mặc định cho màn hình nhỏ, dùng min-width media query để mở rộng dần lên desktop.

4

Đặt tên class rõ nghĩa, nhất quán

Theo quy ước như BEM (.card__title--active) giúp CSS không xung đột và dễ đọc khi dự án lớn dần.

Lỗi thường gặp
❌
Quên box-sizing:border-box — thêm padding làm hộp phình to hơn width đã set, layout bị lệch khó hiểu.
❌
Lạm dụng !important — chữa cháy specificity ngắn hạn nhưng khiến CSS về sau cực khó ghi đè, nên sửa lại độ ưu tiên selector thay vì dùng !important.
❌
absolute mà quên relative ở cha — phần tử bay lệch ra vị trí không mong muốn vì định vị theo <html> thay vì theo card chứa nó.
❌
Thiếu alt cho ảnh, thiếu label cho input — vừa hại SEO vừa hại accessibility, và form khó dùng trên mobile do không click được vào label để focus input.
