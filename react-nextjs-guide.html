React & Next.js là gì & Vì sao dùng chung?

Khái niệm cốt lõi, kiến trúc, quan hệ giữa React và Next.js

React — thư viện dựng giao diện theo Component

React là thư viện JavaScript (không phải framework đầy đủ) để xây dựng giao diện người dùng bằng cách chia UI thành các component tái sử dụng được. Mỗi component quản lý trạng thái (state) riêng, nhận dữ liệu qua props, và tự động render lại khi dữ liệu thay đổi — nhờ cơ chế Virtual DOM.

🧩
Component-based
UI = tập hợp component nhỏ, tái sử dụng được, ghép lại như Lego.
🔄
Declarative
Bạn mô tả UI "trông như thế nào" dựa trên state, React tự lo việc cập nhật DOM.
⚡
Virtual DOM
React so sánh (diff) cây ảo trước/sau, chỉ cập nhật đúng phần DOM thật đã thay đổi.
Next.js — framework full-stack xây trên React

Next.js là framework đóng gói React cùng router, server rendering, tối ưu build, API routes — giúp bạn không phải tự cấu hình Webpack/Babel hay tự viết routing. Next.js thêm khả năng render trên server (SSR/SSG/ISR) mà React thuần (client-only) không có sẵn.

JSX & Components

Cú pháp JSX, function component, cách ghép component lại với nhau

JSX là gì?

JSX là cú pháp mở rộng cho phép viết "HTML" ngay trong JavaScript. Nó được biên dịch thành lời gọi hàm React.createElement(). Mọi component React đều là một hàm JavaScript trả về JSX.

Greeting.jsxCOMPONENT
function Greeting() {
  const name = "Minh";
  return (
    <div className="card">
      <h1>Xin chào, {name}! 👋</h1>
      <p>Đây là JSX — HTML lồng trong JS.</p>
    </div>
  );
}

export default Greeting;
  • Mỗi component phải trả về một root element duy nhất (hoặc dùng <>...</> Fragment).
  • Dùng { } để nhúng biểu thức JavaScript vào JSX.
  • Attribute HTML đổi tên: class → className, for → htmlFor.
  • Tên component luôn viết hoa chữ cái đầu (Greeting, không phải greeting).
Ghép component lại — cây component (Component Tree)
App.jsxCOMPOSE
function Header() {
  return <header><h1>My Shop</h1></header>;
}

function Footer() {
  return <footer>© 2026</footer>;
}

function App() {
  return (
    <>
      <Header />
      <main>Nội dung chính</main>
      <Footer />
    </>
  );
}
💡
Component lớn (App) chứa component nhỏ (Header, Footer) — đây là bản chất "cây component" mà React quản lý để biết cái gì cần render lại khi có thay đổi.

Props & State

Truyền dữ liệu xuống con (props) và dữ liệu nội bộ thay đổi được (state)

Props — dữ liệu truyền từ cha xuống con (chỉ đọc)
UserCard.jsxPROPS
function UserCard({ name, age, onGreet }) {
  return (
    <div className="card">
      <h3>{name} ({age} tuổi)</h3>
      <button onClick={() => onGreet(name)}>Chào</button>
    </div>
  );
}

// Sử dụng — truyền props như thuộc tính HTML
<UserCard name="Lan" age={28} onGreet={(n) => alert(`Chào ` + n)} />
  • Props là read-only — component con không được sửa trực tiếp props nhận vào.
  • Có thể truyền bất kỳ giá trị JS: string, number, object, array, thậm chí hàm callback.
  • Dùng props.children để truyền nội dung JSX lồng bên trong thẻ component.
State — dữ liệu nội bộ, thay đổi khiến component render lại
Counter.jsxSTATE
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0); // state ban đầu = 0

  return (
    <div>
      <p>Bạn đã bấm {count} lần</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  );
}
🔵 SO SÁNH
Props vs State
Props đến từ bên ngoài (component cha), component con không sửa được. State là dữ liệu nội bộ của component, tự thay đổi qua hàm setter và khiến component tự render lại.

useState — quản lý trạng thái

Hook cơ bản nhất, dùng trong gần như mọi component

Cú pháp & quy tắc
useState — ví dụ formHOOK
import { useState } from "react";

function LoginForm() {
  const [email, setEmail] = useState("");
  const [isValid, setIsValid] = useState(false);

  function handleChange(e) {
    const value = e.target.value;
    setEmail(value);
    setIsValid(value.includes("@"));
  }

  return (
    <input value={email} onChange={handleChange}
      style={{ borderColor: isValid ? "green" : "red" }} />
  );
}
  • useState(initial) trả về mảng [giá trị, hàm cập nhật].
  • Gọi hàm setter luôn trigger re-render — không sửa trực tiếp biến state.
  • Khi state mới phụ thuộc state cũ, dùng functional update: setCount(c => c + 1) để tránh bug khi cập nhật liên tiếp.
⚠️
Lỗi thường gặp: Với object/array trong state, phải tạo bản sao mới (setUser({...user, name: "Lan"})) — không mutate trực tiếp, vì React so sánh reference để biết có thay đổi hay không.

useEffect — side effects

Gọi API, subscribe, đồng bộ với hệ thống bên ngoài component

3 dạng dependency array
useEffect — fetch dữ liệu người dùngHOOK
import { useState, useEffect } from "react";

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    let cancelled = false;
    fetch(`/api/users/` + userId)
      .then((res) => res.json())
      .then((data) => { if (!cancelled) setUser(data); });

    return () => { cancelled = true; }; // cleanup — huỷ khi unmount/đổi userId
  }, [userId]); // chỉ chạy lại khi userId thay đổi

  if (!user) return <p>Đang tải...</p>;
  return <h2>{user.name}</h2>;
}
Dependency arrayKhi nào chạyDùng khi nào
useEffect(fn)Sau mỗi lần renderHiếm dùng — dễ gây vòng lặp
useEffect(fn, [])Chỉ 1 lần sau mountFetch dữ liệu ban đầu, setup subscription
useEffect(fn, [a, b])Khi a hoặc b đổiĐồng bộ theo props/state cụ thể
return () => {...}Trước lần chạy tiếp theo & khi unmountCleanup: huỷ subscribe, clear timer, abort fetch

useContext & useRef

Chia sẻ dữ liệu toàn cục & truy cập DOM / lưu giá trị không gây render

useContext — tránh "props drilling"
ThemeContext.jsxCONTEXT
import { createContext, useContext, useState } from "react";

const ThemeContext = createContext(null);

function App() {
  const [theme, setTheme] = useState("dark");
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Toolbar /> {/* con cháu sâu bao nhiêu tầng cũng đọc được theme */}
    </ThemeContext.Provider>
  );
}

function Toolbar() {
  const { theme, setTheme } = useContext(ThemeContext); // không cần truyền qua props
  return <button onClick={() => setTheme(theme === "dark" ? "light" : "dark")}>
    Theme: {theme}
  </button>;
}
useRef — giá trị "sống sót" qua render, không gây render lại
useRef — focus input & đếm renderREF
import { useRef, useEffect } from "react";

function SearchBox() {
  const inputRef = useRef(null);       // tham chiếu DOM element
  const renderCount = useRef(0);   // biến "ẩn", đổi không gây render

  useEffect(() => { inputRef.current.focus(); }, []); // auto-focus khi mount
  renderCount.current++;

  return <input ref={inputRef} placeholder="Tìm kiếm..." />;
}
📝
useRef vs useState: Đổi .current của ref không khiến component render lại. Dùng ref cho: tham chiếu DOM, lưu timer ID, giữ giá trị trước đó — những thứ không cần hiển thị lên UI.

useMemo, useCallback & useReducer

Tối ưu hiệu năng & quản lý state phức tạp

useMemo — cache kết quả tính toán nặng
useMemo — lọc danh sách lớnMEMO
import { useMemo, useState } from "react";

function ProductList({ products }) {
  const [query, setQuery] = useState("");

  const filtered = useMemo(() => {
    return products.filter((p) => p.name.includes(query));
  }, [products, query]); // chỉ tính lại khi products hoặc query đổi

  return <ul>{filtered.map((p) => <li key={p.id}>{p.name}</li>)}</ul>;
}
useCallback — cache một hàm giữa các lần render
useCallback — tránh re-render con không cần thiếtCALLBACK
const handleAdd = useCallback((item) => {
  setItems((prev) => [...prev, item]);
}, []); // hàm giữ nguyên reference qua các lần render

// Kết hợp React.memo ở component con để thực sự có hiệu quả:
const ItemButton = React.memo(function ItemButton({ onAdd }) {
  return <button onClick={onAdd}>Thêm</button>;
});
⚠️
Đừng lạm dụng. useMemo/useCallback chỉ hữu ích khi tính toán thật sự nặng hoặc con được bọc React.memo. Dùng tràn lan làm code phức tạp mà không tăng hiệu năng đáng kể.
useReducer — state phức tạp, nhiều hành động liên quan
useReducer — giỏ hàngREDUCER
import { useReducer } from "react";

function cartReducer(state, action) {
  switch (action.type) {
    case "add":
      return { ...state, items: [...state.items, action.payload] };
    case "remove":
      return { ...state, items: state.items.filter((i) => i.id !== action.payload) };
    case "clear":
      return { ...state, items: [] };
    default:
      return state;
  }
}

function Cart() {
  const [state, dispatch] = useReducer(cartReducer, { items: [] });
  return (
    <button onClick={() => dispatch({ type: "add", payload: { id: 1, name: "Áo" } })}>
      Thêm vào giỏ ({state.items.length})
    </button>
  );
}
💡
Dùng useReducer thay useState khi state có nhiều thuộc tính liên quan hoặc nhiều loại hành động cập nhật — logic tập trung một chỗ, dễ test và debug hơn nhiều useState rời rạc.

Custom Hooks — tái sử dụng logic

Đóng gói logic có state thành hook riêng, dùng lại ở nhiều component

Ví dụ: useFetch — hook gọi API tái sử dụng
useFetch.jsCUSTOM HOOK
import { useState, useEffect } from "react";

function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    setLoading(true);
    fetch(url)
      .then((res) => res.json())
      .then(setData)
      .catch(setError)
      .finally(() => setLoading(false));
  }, [url]);

  return { data, loading, error };
}

// Dùng ở bất kỳ component nào:
function PostList() {
  const { data: posts, loading } = useFetch("/api/posts");
  if (loading) return <p>Đang tải...</p>;
  return <ul>{posts.map((p) => <li key={p.id}>{p.title}</li>)}</ul>;
}
  • Custom hook bắt buộc đặt tên bắt đầu bằng use để React nhận diện đúng quy tắc Hooks.
  • Bên trong có thể gọi các hook khác (useState, useEffect...) — đó là lý do gọi là "hook".
  • Giúp tách logic khỏi UI, test độc lập, và dùng lại ở nhiều component khác nhau.
🚫
2 quy tắc bắt buộc của Hooks (Rules of Hooks): (1) Chỉ gọi hook ở top-level component/hook — không gọi trong if, vòng lặp, hàm lồng. (2) Chỉ gọi hook trong function component hoặc custom hook — không gọi trong hàm JS thường.

Vòng đời Component — 3 giai đoạn

Mount → Update → Unmount, và useEffect ánh xạ vào từng giai đoạn thế nào

1

Mount — component được tạo & gắn vào DOM lần đầu

React gọi hàm component, tính toán JSX, chèn vào DOM thật. Đây là lúc thích hợp để: fetch dữ liệu ban đầu, đăng ký event listener, khởi tạo timer. Tương ứng useEffect(fn, []).

2

Update — render lại khi props/state đổi

Mỗi khi state cha/con hoặc props thay đổi, React render lại, diff Virtual DOM, và chỉ cập nhật phần DOM thật cần thiết. Tương ứng useEffect(fn, [dep]) khi dep đổi giá trị.

3

Unmount — component bị gỡ khỏi DOM

Khi component không còn render nữa (điều kiện đổi, chuyển trang...). Đây là lúc dọn dẹp: huỷ subscription, clear timer/interval, abort request đang chạy — làm trong hàm cleanup mà useEffect trả về.

Minh hoạ đầy đủ 3 giai đoạn trong một component
Timer.jsx — mount / update / unmountLIFECYCLE
import { useState, useEffect } from "react";

function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    console.log("🌱 MOUNT — bắt đầu đếm");
    const id = setInterval(() => setSeconds((s) => s + 1), 1000);

    return () => {
      console.log("🍂 UNMOUNT — dọn dẹp interval");
      clearInterval(id);
    };
  }, []); // [] → chỉ setup 1 lần lúc mount, cleanup lúc unmount

  useEffect(() => {
    console.log("🔄 UPDATE — seconds đổi thành " + seconds);
  }, [seconds]); // chạy mỗi khi seconds thay đổi (bao gồm cả lần mount đầu)

  return <p>Đã trôi qua: {seconds}s</p>;
}

Class Component Lifecycle vs Hooks

Nếu bạn gặp code cũ dùng Class — đây là bảng đối chiếu sang Hooks

Class lifecycle methodTương đương bằng HooksÝ nghĩa
constructor()useState(initial)Khởi tạo state ban đầu
componentDidMount()useEffect(fn, [])Chạy 1 lần sau khi render lần đầu
componentDidUpdate()useEffect(fn, [dep])Chạy khi dependency cụ thể thay đổi
componentWillUnmount()return () => {...} trong useEffectDọn dẹp trước khi component bị gỡ
shouldComponentUpdate()React.memo()Ngăn re-render không cần thiết

So sánh trực tiếp — cùng một componentCOMPARE
// ── Class Component (cách cũ) ──
class Profile extends React.Component {
  constructor(props) {
    super(props);
    this.state = { user: null };
  }
  componentDidMount() {
    fetch("/api/me").then((r) => r.json()).then((u) => this.setState({ user: u }));
  }
  render() {
    return <h2>{this.state.user?.name}</h2>;
  }
}

// ── Function Component + Hooks (cách hiện đại) ──
function Profile() {
  const [user, setUser] = useState(null);
  useEffect(() => {
    fetch("/api/me").then((r) => r.json()).then(setUser);
  }, []);
  return <h2>{user?.name}</h2>;
}
✅
Từ React 16.8 (2019), Hooks là cách viết chuẩn. Class component vẫn hoạt động nhưng gần như không còn được dùng cho code mới — toàn bộ tài liệu chính thức của React hiện dạy Hooks trước tiên.

Ví dụ: Todo App hoàn chỉnh

Kết hợp useState, useEffect, useMemo trong một component thật

TodoApp.jsxFULL EXAMPLE
import { useState, useEffect, useMemo } from "react";

function TodoApp() {
  const [todos, setTodos] = useState(() => {
    const saved = localStorage.getItem("todos");
    return saved ? JSON.parse(saved) : [];
  });
  const [text, setText] = useState("");
  const [filter, setFilter] = useState("all"); // all | active | done

  // Đồng bộ localStorage mỗi khi todos đổi
  useEffect(() => {
    localStorage.setItem("todos", JSON.stringify(todos));
  }, [todos]);

  function addTodo() {
    if (!text.trim()) return;
    setTodos((prev) => [...prev, { id: Date.now(), text, done: false }]);
    setText("");
  }

  function toggleTodo(id) {
    setTodos((prev) => prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));
  }

  // Lọc danh sách — chỉ tính lại khi todos hoặc filter đổi
  const visibleTodos = useMemo(() => {
    if (filter === "active") return todos.filter((t) => !t.done);
    if (filter === "done") return todos.filter((t) => t.done);
    return todos;
  }, [todos, filter]);

  return (
    <div>
      <input value={text} onChange={(e) => setText(e.target.value)}
        onKeyDown={(e) => e.key === "Enter" && addTodo()} />
      <button onClick={addTodo}>Thêm</button>

      <div>
        {["all", "active", "done"].map((f) => (
          <button key={f} onClick={() => setFilter(f)}>{f}</button>
        ))}
      </div>

      <ul>
        {visibleTodos.map((t) => (
          <li key={t.id}
            style={{ textDecoration: t.done ? "line-through" : "none" }}
            onClick={() => toggleTodo(t.id)}>
            {t.text}
          </li>
        ))}
      </ul>
    </div>
  );
}

export default TodoApp;
📝
Điểm học được: khởi tạo state "lười" bằng hàm (useState(() => ...)) để chỉ đọc localStorage 1 lần, functional update (prev =>) khi state mới phụ thuộc state cũ, và useMemo để tránh lọc lại danh sách mỗi lần gõ phím vào ô input.
